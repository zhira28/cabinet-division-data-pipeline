# Cabinet Division Scraping & Document Processing Pipeline

An Apache Airflow pipeline that scrapes Laws and Policies from the Cabinet Division of Pakistan website, stores policy metadata in MongoDB, downloads the associated PDF documents, and converts the PDFs into Markdown files.

## Pipeline Overview

```text
Cabinet Division Website
          |
          v
      Web Scraper
          |
          v
       MongoDB
   (Policy Metadata)
          |
          v
     PDF Downloader
          |
          v
       PDF Files
          |
          v
   PDF to Markdown
      Converter
          |
          v
    Markdown Files
          |
          v
     MongoDB Update
```

## Pipeline Tasks

The Airflow DAG is named:

```text
cabinet_division_pipeline
```

The tasks execute in the following order:

```text
scrape_policies
       |
       v
download_pdfs
       |
       v
convert_pdfs_to_markdown
```

### 1. Scrape Policies

The scraper retrieves policy information from the Cabinet Division website.

The scraped information includes:

- SR.NO
- Title
- Date
- PDF URL

The data is stored in MongoDB.

### 2. Save to MongoDB

MongoDB stores the scraped policy metadata in:

```text
Database: cabinet_division_db
Collection: policies
```

The `sr_no` field is used as the unique identifier.

The pipeline uses MongoDB `upsert`, so running the scraper multiple times does not unnecessarily create duplicate records for the same SR.NO.

### 3. Download PDFs

The PDF downloader reads the PDF URL from MongoDB and downloads the corresponding document.

Downloaded files are stored in:

```text
data/pdfs/
```

The filenames follow this format:

```text
SR_NO_Title.pdf
```

Unsafe characters in titles are replaced with underscores.

### 4. Convert PDFs to Markdown

The PDF converter uses PyMuPDF4LLM to convert downloaded PDF documents into Markdown.

Markdown files are stored in:

```text
data/markdown/
```

The Markdown filename corresponds to the PDF filename.

### 5. Update MongoDB

After successful processing, the MongoDB document is updated with:

```text
pdf_path
markdown_path
downloaded
converted_to_markdown
```

Example:

```json
{
    "sr_no": 1,
    "title": "Example Policy",
    "date": "2024-01-01",
    "pdf_url": "https://example.com/policy.pdf",
    "pdf_path": "data/pdfs/1_Example Policy.pdf",
    "markdown_path": "data/markdown/1_Example Policy.md",
    "downloaded": true,
    "converted_to_markdown": true
}
```

## Configuration

Create a `.env` file in the project root.

Example:

```env
MONGO_URI=mongodb://host.docker.internal:27017
MONGO_DATABASE=cabinet_division_db
MONGO_COLLECTION=policies
SOURCE_URL=https://cabinet.gov.pk/Policies
PDF_DIRECTORY=data/pdfs
MARKDOWN_DIRECTORY=data/markdown
REQUEST_TIMEOUT=30
MAX_RETRIES=3
```

A template is provided in:

```text
.env.example
```

Do not commit or share `.env` if it contains private credentials or secrets.

## Troubleshooting

### Broken DAG: No module named `pymongo`

Make sure `pymongo` is present in:

```text
requirements.txt
```

Then rebuild the Docker image:

```powershell
docker compose build --no-cache
docker compose up -d
```

Do not rely on manually installing packages inside the running container because those changes can be lost when the container is recreated.

### Broken DAG: No module named `pymupdf4llm`

Make sure `pymupdf4llm` is present in:

```text
requirements.txt
```

Then rebuild:

```powershell
docker compose build --no-cache
docker compose up -d
```

### MongoDB connection refused

If Airflow reports:

```text
localhost:27017: Connection refused
```

make sure the MongoDB connection string is:

```text
mongodb://host.docker.internal:27017
```

rather than:

```text
mongodb://localhost:27017
```

because `localhost` inside the Airflow container refers to the Airflow container itself.

### PDFs are not appearing in the local project folder

Make sure `docker-compose.yaml` contains:

```yaml
volumes:
  - ./data:/opt/airflow/data
```

This maps the local `data` directory to the Airflow container.

## Important Notes

- The `data/pdfs/` and `data/markdown/` directories contain generated files.
- The `.env` file should not be committed if it contains secrets.
- `.env.example` should be shared as the configuration template.
- Python dependencies are installed during Docker image creation.
- MongoDB is currently expected to run outside Docker on the host machine.
- Airflow is responsible for orchestrating the complete scraping and document-processing workflow.
